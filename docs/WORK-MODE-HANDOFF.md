# K-방산 ATLAS · 다른 PC / WORK 모드 인계 프롬프트

아래 내용을 새 WORK 작업의 첫 프롬프트로 사용한다. 최신 GitHub main을 복제한 작업 폴더를 연다. ZIP은 이전 인계 당시의 보조 스냅샷이므로 최신 GitHub 파일에 무조건 덮어쓰지 않는다.

## 1. 프로젝트와 인계 상태

당신은 기존 K-방산 ATLAS 웹앱을 이어서 개선하는 개발자이자 3D 전시 제작 담당자다. 새 앱을 처음부터 만들지 말고 기존 결과물을 보존하며 보완하라.

- GitHub: https://github.com/ai-studying-man/DAPA-DASHBOARD
- GitHub Pages 설정 주소: https://ai-studying-man.github.io/DAPA-DASHBOARD/
- 이번 갱신 전 기준 커밋: `1e84402d3b876066c09a0132ef1f4bd7d13b2f4a`. 이후 모바일 슬라이드·K2/K9·인계 문서의 갱신 커밋은 Git 이력에서 확인한다.
- 모바일 슬라이드 v15~v17과 K2/K9 체험 v18을 저장소 반영 대상으로 묶었다. 이 문서를 포함한 최신 main이 기준이다. ZIP은 반영 전 작업 폴더 사본이며 이후 원격 변경을 덮어쓰는 기준이 아니다.
- Pages 주소가 존재한다는 것과 최신 로컬 결과가 배포됐다는 것은 다르다. 이 인계에서 배포 성공을 새로 확인하지 않았다.
- 이전에 제공한 ZIP의 `SOURCE-MANIFEST.json`은 그 스냅샷의 SHA-256과 기준 커밋이다. 저장소의 현재 HEAD를 증명하지 않으며 `.git`은 ZIP에 없다.
- 과거 README·보고서는 버전별 개발 기록이 섞여 있다. 현재 소스와 이 인계 문서, 실제 실행 결과를 우선한다.

## 2. 목적과 사용자

방위사업청을 중심으로 우리나라의 무기체계 사업, 기업·기관의 역할, 공개된 수출 사례와 기술을 쉽게 이해하는 홍보·전시 웹앱이다. 전시회, 박람회, 세미나, 간부 대상 브리핑과 해외 관람객 안내에 사용한다.

**모바일 세로 화면을 최우선**으로 하며 PC 가로 화면과 최종 키오스크 터치 조작을 함께 지원한다. 어린이도 이해할 수 있는 쉬운 한국어, 짧은 설명, 큰 조작 영역을 유지한다. 공모전 제출 형식보다 실제로 동작하는 체험을 우선한다.

## 3. 실행과 배포

Node.js 22 환경을 사용한다. 일반적인 로컬 실행:

```sh
npm ci
npm run dev
# http://127.0.0.1:5173/
```

배포물 확인:

```sh
npm run build
npm run preview
# http://127.0.0.1:4173/
```

- `predev` / `prebuild`가 `scripts/prepare-cesium.mjs`를 실행해 설치된 Cesium의 정적 자산을 `public/cesium/`에 준비한다. 이 생성 폴더는 ZIP과 Git에서 제외된다.
- Vite `base: './'`을 유지한다. GitHub Pages의 `/DAPA-DASHBOARD/` 하위 경로에서 사진·GLB·폰트·동적 모듈이 동작해야 한다. 루트 절대 경로로 바꾸지 않는다.
- `.github/workflows/deploy-pages.yml`: main push → Node 22 → npm ci → build → dist 업로드 → Pages 배포.
- 권장 인계: GitHub main을 clone → npm ci → npm run dev. 이전 ZIP을 독립 실행할 수도 있지만, 최신 clone 위에 덮어쓰면 변경이 되돌아갈 수 있으므로 먼저 diff를 검토한다.
- 다른 PC에서 `127.0.0.1`은 그 PC 자체다. 기존 PC의 로컬 주소는 이동 가능한 배포 URL이 아니다.

## 4. 기술 구성

- HTML5 / CSS / ES Modules 기반 vanilla JavaScript. React나 서버 API 기반 프로젝트가 아니다.
- Three.js `0.180.0`: 로컬 GLB 외형 관찰, 카메라, 조명, 재질과 부품 조작.
- Cesium `1.146.0`: 실제 위성·항공 영상과 고도 지형, 환경 시연.
- Vite `7.3.7`: 개발·빌드·상대 경로 배포.
- Lenis `1.3.26` 의존성과 과거 홈 모션 설계가 남아 있다. **현재 슬라이드 이동은 native scrollTo + CSS scroll snap이 중심**이다. 라이브러리 설치 여부를 현재 전환 엔진 사용과 혼동하지 않는다.
- Noto Sans KR 로컬 WOFF2 및 `@fontsource/noto-sans-kr` `5.2.6`. 글자 추가 시 폰트 서브셋 누락을 확인한다.
- `speechSynthesis` / `SpeechSynthesisUtterance`: 브라우저·OS의 해당 언어 음성에 의존하는 TTS.
- 백엔드, 실시간 전력 데이터 수집, 인증 서비스, 상용 디지털 트윈 엔진은 구현돼 있지 않다.

## 7. 위성 지도·환경·3D 범위

- Esri World Imagery + ArcGIS WorldElevation3D Terrain3D. 실제 고도 비율 1:1.
- 지상 산악/평지, 연안, 해상, 수중, 공중, 우주 관측 환경. 카메라 복원·확대·축소 및 환경별 시점.
- KAAV·FA-50·도산안창호급·누리호 로컬 외형 GLB, 별도 T-80U 공개 자산. **T-80U를 K2라고 표시하지 않는다.**
- 일부 장비는 실제 사진·외부 뷰어·준비 상태다. 모든 장비가 동일 수준의 고정밀 3D는 아니다.
- 해치 등 기존 관측 시점은 외형 기반 추정이다. 검증된 승무원실이 아니다. 무인 장비에 탑승 시점을 만들지 않는다.
- 지도의 10초 로딩 기한, 네트워크/WebGL 오류 안내, 재시도·영상 대체·복귀 흐름이 있다.
- 최근 K9 지도 시연에서 GLB 연결과 지형 높이 샘플링은 관찰했지만, 타일 로딩이 기한을 초과했다. **지도 위 정상 렌더링 성공은 최근 검증하지 못했다.** 다음 PC의 실제 네트워크와 WebGL에서 우선 재확인한다.

## 8. K2/K9 v18 구현 결과와 가장 중요한 다음 목표

### 구현됨

- 로컬 `k2-exhibit.glb`, `k9-exhibit.glb`. 각각 1,507,040 / 1,495,760 bytes, 약 2만 삼각형. JavaScript 절차적 형상 생성기로 제작한 독립 외형 초안.
- 차체 `Hull`, 포탑 `Turret`, 포신 `Gun`, 주행부 `RunningGear`, 표식 `Markings`의 독립 그룹. Gun은 Turret 하위, Turret은 Y축, Gun은 로컬 X축 회전. 미터 단위, +Y 위 / -Z 전방.
- 정면·후면·좌·우·상면·초기 시점, OrbitControls 회전·확대, 구조선, 표식 표시, 부품 강조·분리, 포탑·포신 수동 조작, 예시 부품 동작, 독립 자동 둘러보기, 정지·원위치.
- 화면 비율과 변경된 외형 경계에 맞춘 카메라 프레이밍, 그림자와 조명.
- 실제 장비 사진 / 사진 사용 조건 / 제조사 소개 / 모델 출처 비교 패널.
- 4개 언어 UI. 모바일은 조작 이름을 위에, 슬라이더·수치를 아래에 배치. 스위치 2열, 행동 버튼 전체 너비, 부품 선택 별도 행.
- 숨김·폐기 시 렌더링 루프/이벤트/관찰자/geometry/material/texture 정리. 오류 상태와 재시도 UI. fault injection으로 복구를 실증한 것은 아니다.

### 사용자가 바로잡은 방향 — 최우선으로 따른다

**사용자는 장난감·애니메이션 같은 모형을 더 정교하게 꾸미는 결과를 원하지 않는다. 실제 장비 사진에 기반한 현실감 있는 외형·재질을 원한다. 현재 K2/K9는 조작 기능의 초안일 뿐, 요구한 실사화 완성본이 아니다.**

1. K2부터 사용 허가된 정면·측면·후면·상면 사진과 가능하면 회전 촬영 영상을 확보한다. 그다음 K9에 적용한다.
2. 사진별 출처·권리·장비 형식/연식 차이를 기록하고 다면 참조판을 만든다. 서로 다른 형식을 섞어 모델링하지 않는다.
3. 사진과 모델을 같은 방향으로 비교하며 실루엣, 장갑 경사, 포탑, 차륜, 궤도, 포신, 관측장비를 재구성한다. 보이지 않는 면은 추정으로 구분한다.
4. 사진 기반 UV/PBR 재질, 위장 패턴, 금속/고무/유리, 노멀·거칠기·AO와 디테일을 제작한다. 단순 컬러 도형에 조명만 강화한 것을 실사화라고 부르지 않는다.
5. 필요하면 Blender·사진측량·다시점 재구성 등 사용 가능한 제작 도구를 선택한다. 한 장의 사진만으로 정확한 전체 입체를 복원했다고 주장하지 않는다. 현재 .blend 원본·제조사 CAD·정합된 4면 도면은 없다.
6. 웹용 GLB로 최적화하되 기존 피벗·부품 조작을 유지한다. 사진 수준 텍스처와 네트워크·GPU 비용의 균형을 실제 모바일에서 확인한다.
7. 실제 사진과 같은 카메라 각도의 결과 이미지를 나란히 보여 차이와 개선을 평가한다. 실사화 개선 근거 없이 조작 화면만으로 완료 보고하지 않는다.
8. 위성 지형의 빛·그림자·색·접지 상태를 맞춘다. 검증된 내부 자산이 없다면 실제 탑승자 내부 시점은 미구현으로 남긴다.

CAD가 없어도 공개 사진 기반 현실감 개선은 가능하다. 승인 자산이나 CAD가 필요한 부분과 가능한 작업을 구분하고, 자료가 없는 이유로 가능한 개선까지 멈추지 않는다. 제조사 전시 페이지의 비공개 모델을 무단 추출·재배포하지 않는다.

## 9. 디자인 시스템 — 보존 기준

- 기존 밝은 표면·짙은 남색 텍스트·파란 행동 버튼. 토스의 큰 미디어·문구 전개·부드러운 이동을 참고한 자체 CSS이며 토스 공식 라이브러리/완전 복제는 아니다.
- 색: bg `#f5f7fa`, panel `#fff`, elevated `#edf2f8`, line `#d0d9e5`, text `#172b4d`, muted `#52657d`, accent `#145caa`, 선택 배경 `#e7f0fc`.
- 영역색: 지상 `#176348`, 해상 `#096681`, 공중 `#225da9`, 우주 `#654aa0`.
- 간격 토큰: 4/8/12/16/20/24/32/40/48/64px. 본문 크기: 12/14/16/18/22/28/36px. radius: 8/12/20/28px.
- 글꼴 Noto Sans KR, weight 400/500/700. 홈·슬라이드 제목은 별도 clamp 반응형 크기. `src/tokens.css`, `src/story.css`, `DESIGN.md`가 기준이다.
- 기본 터치 목표 48px. 짧은 라벨, 같은 역할의 같은 크기·색·정렬. 키보드 포커스는 파란 accent로 명확하게 표시한다.
- 모바일 375px 및 작은 높이에서도 홈의 영상·문구·다음·언어 선택이 잘리지 않아야 한다. 필요한 경우 정보를 별도 장으로 나눈다.
- 관련 정보는 가깝게, 다른 정보는 간격을 둔다. 가운데 제목/본문과 좌측 파란 장 캡션의 역할을 구분한다. 한글 조사·짧은 문장, 일본어·중국어·긴 영문이 부자연스럽게 끊기거나 넘치지 않게 한다.
- 모션은 페이지 이동·선택·부품 관찰에 연결한다. 장식적 상시 흔들림은 추가하지 않는다. prefers-reduced-motion, 비활성 탭, 다이얼로그, 닫기 시 중지·정리를 유지한다.
- 실제 DOM/CSS/JS를 사용한다. 화면 PNG를 붙여 UI로 대체하지 않는다.

## 10. 다국어·음성·미디어

- UI/장비/근거 문구 한·영·일·중 리소스, 원문 보존 후 가역적 언어 변경, aria-label/대체 텍스트 번역, 고유명사·출처·라이선스 보존.
- KAAV·FA-50·도산안창호급·누리호의 12개 부위 관람 안내와 자막, TTS 연결.
- 실제 음성은 OS 설치 음성과 브라우저 정책에 의존한다. 4개 언어가 모든 PC에서 발화 성공했다고 주장하지 않는다. 미설치/오류 때 자막 유지·자동 진행 중지.
- 언어 변경·화면 닫기·탭 비활성 시 음성/미디어를 정리한다. 자동 음성은 사용자 재생 동작과 전시 환경을 고려한다.
- 홈 영상 `public/media/k-defense-story.mp4` 약 7MB. 사용자 제공 영상의 로컬 사본이며, 외부 PC의 원래 카카오톡 파일 경로에 의존하지 않는다. 권리·기관 로고 사용 조건은 전시/공개 배포 시 별도 확인이 필요하다.

## 11. 성능과 검증 — 측정된 것만 주장

- 최근 production build 성공, 67 modules. 초기 JS 약 334.89KB / gzip114.64KB, lazy 모델 뷰어 약 607.09KB / gzip156.57KB. 소폭 변경될 수 있으므로 재빌드 출력으로 갱신한다.
- Vite의 500KB 초과 경고는 남아 있다. 경고 한도만 높여 해결한 것처럼 표시하지 않는다.
- native 뷰어 DPR 상한1.5, 그림자1024, 15초 자산 fetch 기한, 화면 비노출 시 루프 중지, GLB 지연 로딩.
- K2/K9 최근 화면 관찰: 375×812, 768×977, 1280×900, 4개 언어, 시점·조절·분리·구조선·동작·사진 비교. 30개 캡처와 독립 화면/구조 검토 통과.
- 이 작업에서 자동 테스트는 새로 만들거나 실행하지 않았다. 기존 qa:* 스크립트 존재와 이번 버전의 실행 성공을 혼동하지 않는다.
- FPS, Lighthouse, 실기기 성능 수치는 이번 버전에서 측정하지 않았다. `60fps 보장`, `전 장비 고정밀`, `완전 오프라인`, `실제 키오스크 검증 완료`라고 표현하지 않는다.
- 3D 자산의 missing-file / context-loss 복구는 소스 검토 수준이며 최근 fault injection 미실시. 외부 지도 성공은 앞서 기술한 대로 미확인이다.

## 13. 다음 작업의 우선순위와 보고 형식

1. 최신 GitHub main의 커밋을 확인하고 K2/K9 native 파일과 story-deck.js 존재를 확인한 뒤 설치·빌드·실행한다.
2. 모바일 홈/슬라이드/지도/기존 체계 관람을 먼저 확인하여 기준 화면을 보존한다.
3. **K2 사진 기반 현실감 개선**을 먼저 실제 결과물로 만들고, 같은 기준으로 K9를 진행한다. 현재 단순 도형에 세부 도형만 더 붙이는 방향으로 되돌아가지 않는다.
4. 사진·원문·사용권·형상 판단 근거를 기록하고, 가능한 모델링을 수행한다. 필요한 자산이 정말 없을 때만 구체적인 누락 자료를 요청한다.
5. 기존 조작/다국어/접근성/반응형/실사 비교를 유지하며 모델을 교체한다. 지도 타일·접지·광원 문제를 실제 환경에서 확인한다.
6. 변경 범위에 맞는 빌드와 실제 화면 검증을 수행한다. 저장소·환경의 지침을 따르며 테스트 실행은 사용자 요청과 현재 작업 지침에 맞춘다.
7. 보고는 **수정한 결과 → 실제 화면/파일 → 확인한 동작 → 남은 한계** 순서로 짧게 한다. 계획만 제시하거나 구현하지 않은 기능을 완료로 쓰지 않는다.
8. 기존 사용자 수정과 미커밋 파일을 보존한다. commit/push가 요청되면 변경을 검토·분리하고 결과 해시를 보고한다. 이 프롬프트 자체를 main 강제 푸시·외부 메시지·유료 구매 권한으로 해석하지 않는다.

완료 기준: 사진과 나란히 비교했을 때 K2/K9의 외형·재질 현실감이 실제로 개선되고, 기존 모바일 전시 흐름과 부품 조작이 유지되며, 검증된 사실과 추정·미구현 영역이 명확해야 한다.
