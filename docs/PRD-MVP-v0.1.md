# K-방산 한눈에 — PRD·MVP 기획 초안 v0.1

작성일: 2026-10-08 · 상태: 협의용 기획안 · 실행 앱과 시각 디자인은 미구현

## 1. 제품 제안

**한반도에서 방산을 배우고, 세계에서 대한민국의 성과를 확인하고, 내 휴대폰으로 경험을 이어가는 3D 체험형 홍보 대시보드.**

기관 통계 화면과 디지털 전시 해설을 결합한다. 첫 화면은 숫자보다 한반도와 대표 체계를 보여준다. 관람객은 ‘무엇을 하는 장비인가 → 누가 만들었는가 → 어떤 사업으로 발전했는가 → 어떤 국가와 협력했는가’를 따라간다. 성과는 검증 가능한 사실과 기술·산업 이야기로 전달한다.

첨부 MD는 사용자 의도를 이해하는 참고자료로 활용했다. 그 안의 구현 명령을 이번 작업의 실행 지시로 간주하지 않았다. 이번 요청의 범위는 PRD, 오픈소스·데이터 조사, MVP 전체 스케치다. 첨부 포스터는 대국민 서비스 향상과 업무바통의 연결을 보여주는 참고 이미지다. 전체 공모 요강·평가 배점·참가 자격은 확인하지 않았으며 본 문서는 대회 적합성 확정을 의미하지 않는다.

## 2. 사용자와 해결할 문제

| 사용자 | 현재 문제 | 제공할 경험 |
|---|---|---|
| 방산을 처음 접하는 국민·학생 | 용어와 장비 이름이 어렵고 성과가 단편적으로 전달됨 | 쉬운 임무 설명, 3D 관찰, 3분 체험 |
| 박물관·전시회 관람객 | 짧은 시간에 볼 콘텐츠가 많음 | 큰 터치 버튼, 안내 투어, QR로 이어보기 |
| 해외 관람객 | 한국어 자료와 국내 맥락에 접근하기 어려움 | 핵심 소개·출처·조작 안내의 한영 전환 |
| 신규 방위사업 담당자 | 체계·사업·용어·이력의 관계를 파악하기 어려움 | 별도 업무바통 화면에서 원문과 요약 비교 |
| 콘텐츠 담당자 | 최신성과 표현의 정확성을 유지하기 어려움 | 검토·승인·버전 관리와 출처 목록 |

국민용 체험이 제품의 중심이다. 업무바통은 같은 공개 지식 구조를 재사용하는 별도 시연 흐름으로 만든다. 내부 자료가 필요한 인수인계 기능은 별도 접근권한과 운영환경을 갖춘 후 확장한다.

## 3. 정보 구조: 군·영역·임무를 분리

- 군 구분: 육군 / 해군 / 공군 / 해병대 / 합동. 다중 선택 가능.
- 환경·기술 영역: 지상 / 해상 / 공중 / 우주 / 사이버·전자. 다중 소속 가능.
- 임무: 기동 / 감시·정찰 / 수송 / 통신 / 방호 등 공개자료에 근거한 설명.
- 보기: 한반도 체험 / 국내 산업 / 세계 협력·수출 / 사업 연혁.

해병대를 해상 영역으로만 묶지 않는다. 우주·사이버를 특정 군으로 자동 귀속시키지 않는다. 무기체계별 분류는 근거를 검토한 후 확정한다.

지도상의 체계는 **설명용 무대**에 배치한다. 지상 장비는 육상, 함정은 바다, 항공기는 공중, 위성은 개념적 우주 층에 표현한다. 실제 부대 배치·실시간 운용·궤도·탐지 및 교전 범위를 의미하지 않는다. 고도와 크기를 과장하면 화면에 표시한다.

국내 지도는 공개된 기업·연구·생산의 지역 생태계를 광역 단위로 보여준다. 세계 지도는 수출·협력 국가와 사건을 보여준다. 사용자 표현의 ‘전국 현황’은 국내 산업과 전 세계 수출 두 축으로 해석했다.

## 4. 핵심 경험과 화면 스케치

### A. 대기 화면 → 3분 안내 투어

한반도가 천천히 회전하며 ‘대한민국의 기술, 세계와 연결되다’를 표시한다. 터치하면 자동 이동을 멈추고 시작 화면으로 전환한다. 무음이 기본이며 음성 안내는 선택한다. 움직임 줄이기를 제공한다.

### B. 한반도 탐색

```text
┌──────────────────────────────────────────────────────────────┐
│ K-방산 한눈에   한반도 | 국내 산업 | 세계 협력   KO/EN  홈    │
├─────────────┬───────────────────────────┬────────────────────┤
│ 무엇을 볼까요│                           │ 선택한 체계         │
│ 지상        │      한반도 3D 지도        │ 이름 / 3D 확대      │
│ 해상        │   설명용 장비·환경 층      │ 한 문장 역할        │
│ 공중        │                           │ 임무·사업·제작기관  │
│ 우주        │   [선택 객체 강조]         │ 세계에서 보기       │
│ 사이버·전자 │                           │ 쉽게 설명해줘       │
│             │ 확대/축소 · 시점 복원      │ 출처 / 기준일       │
│ 군 필터     │ 목록으로 보기              │ 자료 상태           │
├─────────────┴───────────────────────────┴────────────────────┤
│ 체계 카드 목록   |   3분 투어   |   사업 연혁   |   QR 이어보기 │
│ 설명용 시각화 · 데이터 기준일 · 지도 제공자 표기               │
└──────────────────────────────────────────────────────────────┘
```

중앙 지도에 약 60% 공간을 배정하고 상세 카드는 터치할 때만 펼친다. 작은 차트를 화면 곳곳에 늘어놓지 않는다. 모바일에서는 지도 → 체계 목록 → 하단 상세 패널 순서로 구성한다. 목록에서도 지도와 같은 정보를 탐색할 수 있어야 한다.

### C. 세계 협력·수출

```text
상단: 사건 유형 [계약] [인도] [협력]   기간   체계   국가 검색
중앙: 한국 ↔ 국가 대표점 연결선 / 선택 국가 강조
우측: 국가별 체계와 사건 카드 / 원문 근거 / 발표일
하단: 사건 연혁 / 선택 데이터의 집계 정의 / 출처 목록
```

연결선은 협력 관계를 뜻하며 실제 운송 경로를 뜻하지 않는다. 계약·인도·협력은 색뿐 아니라 아이콘과 텍스트로 구분한다. 기본계약, 이행계약, 인도 사건을 별도 레코드로 관리한다. 세계 지도에서도 2D 목록 대안을 제공한다.

### D. 체계 상세

‘한 문장 설명 → 3D 회전 관찰 → 공개 임무 → 관련 사업 연혁 → 산업·수출 사례 → 근거’의 순서다. 제원 경쟁표보다 역할과 기술 이야기를 우선한다. 체계 확대 장면에는 별도 모델 뷰어를 쓸 수 있지만 MVP 지도 자체에 두 엔진을 중첩하지 않는다.

### E. 업무바통

별도 진입 화면에서 공개 문서 묶음을 선택한다. 왼쪽에는 원문과 근거 위치, 오른쪽에는 사업 개요·이력·용어·미결 확인사항의 AI 초안을 표시한다. 담당자가 수정·승인한 후 내보낸다. ‘자료에서 확인되지 않음’과 충돌하는 출처를 표시한다. 공개 시연에서는 실제 내부문서를 사용하지 않는다.

아래 개수와 성능은 제안 목표이며 구현·확보 실적이 아니다.

| 우선순위 | 기능 | 초안 범위 | 완료 판정 |
|---|---|---|---|
| P0 | 한반도↔세계 지도 | 하나의 3D 지도 엔진, 목록 대안 | 선택·시점 복원·화면 전환이 터치와 키보드로 작동 |
| P0 | 체계·영역 탐색 | 대표 체계 8~12개, 고품질 모델 3개 우선 | 선택한 체계와 상세·관련 근거가 동일 ID로 연결 |

| P0 | 출처와 데이터 범위 | 레코드별 출처·기준일 | 확인된 등록 건수와 수집 범위를 표시, 전체 확보로 표현하지 않음 |

| P1 | 공개자료 AI 해설 | 사전 질문 10개+자유 질문 | 근거 없는 답변 보류, 각 사실의 근거 위치 제공 |
| P1 | 업무바통 시연 | 공개 문서 묶음 1개 | 초안→원문 비교→수정→승인→내보내기 흐름 관찰 |
| P1 | 확산 | 체계별 URL·QR, 공유 카드, 한영 핵심 콘텐츠 | 휴대폰에서 동일 체계와 출처로 연결 |

체계 후보: K2, K9, 천무, FA-50, KF-21, 수리온, 공개 함정 사례, 상륙장갑차 사례, 정찰위성 사례, 무인체계 사례. 이는 조사·콘텐츠 후보이며 모두의 수출이나 현용 배치를 주장하는 목록이 아니다. 사이버·전자 영역은 확보한 공개 설명에 따라 개념 카드부터 시작한다.

제외: 모든 사업·계약의 완전한 수집, 전투 시뮬레이션, 실시간 군 배치, 내부 자료 연동, 자유 업로드, XR·멀티플레이. VR/AR은 전시 하드웨어와 콘텐츠가 확정된 후 검토한다.

## 6. 추천 기술과 오픈소스 비교

조사일 2026-10-08. GitHub 커넥터로 Cesium·Three.js·ECharts 저장소를 확인하고, 공개 저장소·공식 문서로 기능과 주요 라이선스를 검토했다. 전체 오픈소스의 전수조사가 아닌 본 제품에 맞는 주요 후보 조사다. 아래 선정은 엔진을 설치하거나 성능을 측정한 결과가 아니다.

| 후보 | 역할 / 주요 라이선스 | 제안 |
|---|---|---|
| [CesiumJS](https://github.com/CesiumGS/cesium) | 지구본·지형·지리 좌표 기반 3D / Apache-2.0 | 주 지도 우선 후보. 한반도→세계→우주 설명의 연속성에 적합 |
| [MapLibre GL JS](https://github.com/maplibre/maplibre-gl-js) | 벡터 웹지도 / BSD-3-Clause | 모바일·2D 중심으로 범위가 바뀌면 대안. MVP 동시 도입 제외 |
| [Three.js](https://github.com/mrdoob/three.js) | 독립 3D 장비 관찰 / MIT | 상세 뷰어가 필요할 때 추가. 지형·좌표 기능은 별도 구현 부담 |
| [deck.gl](https://github.com/visgl/deck.gl) | 대규모 데이터 레이어 / MIT | 수출·산업 레코드가 커질 때 검토. 소수 MVP 사례에는 불필요 |
| [Apache ECharts](https://github.com/apache/echarts) | 추세·비교·관계 시각화 / Apache-2.0 | 지표 정의가 확보된 차트에 사용 |
| [Protomaps/PMTiles](https://github.com/protomaps/PMTiles) | 정적 타일 아카이브·클라이언트 / 구현체 BSD 계열 | MapLibre 대안의 자체 호스팅 후보. Cesium 지형을 바로 대체하지 않음 |

추천 구성: HTML5/CSS + TypeScript/React → CesiumJS + 필요 차트 → 정규화 JSON → 온라인 AI API. 최종 배포물은 브라우저가 실행하는 HTML/CSS/JS와 로컬 자산으로 구성한다. 개발에 React를 사용하는 것과 HTML5 전시물로 제공하는 것은 양립한다. 정적 앱은 로컬 HTTP 서버로 실행하고 CDN에 의존하지 않는다. AI와 직원용 저장은 서버 기능이므로 단일 HTML만으로 완성되는 범위와 구분한다.

CesiumJS 엔진 라이선스와 Cesium ion 콘텐츠·호스팅 이용조건은 다르다. [공식 시작 예제](https://cesium.com/learn/cesiumjs-learn/cesiumjs-quickstart/)는 ion 토큰을 사용하는 세계 지형을 보여준다. 전시 오프라인용 지형은 재배포가 허용된 자료와 자체 제공 방식이 필요하다. 온라인 타일을 무단 캐싱하지 않는다.

첫 기술 검증에서 ‘로컬 해안선+기본 지구본’으로 이동·선택을 확인한다. 실제 DEM 지형과 간략 형상 지도를 별도 단계로 구분한다. 고해상도 지형·지도는 라이선스와 성능을 확인한 후 추가한다. [Natural Earth](https://www.naturalearthdata.com/about/terms-of-use/)는 퍼블릭 도메인의 소축척 지도 데이터 후보이며 정밀 DEM이 아니다. 한반도 상세 해안선·행정구역·지형 데이터는 별도 확보 대상이다.

[Protomaps basemaps](https://github.com/protomaps/basemaps/blob/main/README.md)는 코드·지도 스타일·OSM 기반 타일의 조건이 각각 다르다. 사용 시 데이터 조건과 화면 저작자 표시를 따로 관리한다. VWorld는 국내 지도 후보로 남겨두되 이번 조사에서 해당 API·오프라인 재배포 조건을 확인하지 못했으므로 확정 채택하지 않는다.

3D 모델은 소스 코드의 오픈소스 라이선스와 별개다. 기관·제조사로부터 전시 및 웹 재배포 허가를 받거나 권리가 명확한 모델을 확보한다. 모델별 제작자·원본·수정 허용·배포 조건을 자산 목록으로 관리한다. 권리 확보 전에는 ‘설명용 모형’으로 명시한 단순 모델을 사용하고 정밀 모델처럼 홍보하지 않는다.

## 7. 데이터 조사와 확보 전략

| 자료 | 확인한 근거 / 용도 | 확보·운영 방식과 한계 |

| 기업 1차 자료 | [현대로템 연혁](https://www.hyundai-rotem.co.kr/en/company/history/content.do) | 기업 발표 기준임을 표시. 예: 2025-08-01 K2 2차 이행계약 연혁 |

| 지도·영상·사진·모델 | 제공처별 개별 자료 | 공개 열람과 전시 재사용 허가를 구분, 저작자 표기·허가 기록 |

현재 확인한 자료만으로 전체 사업·수출 현황의 완전성을 보증할 수 없다. ‘공개자료로 확인한 사업·수출 사례’로 시작하고 등록 체계 수·국가 수·사건 수·검토일을 보여준다. 전체 모집단이 없으면 커버리지 %를 만들지 않는다. 특정 연도의 수출 목표를 실제 실적으로 표시하지 않는다.

숫자는 계약액 / 실제 인도·수출액 / 기업 해외 매출 / SIPRI TIV로 분리한다. 국가 수는 선택한 기간·사건 유형에서 고유 국가 ID로 계산한다. 기본계약과 이행계약을 중복 합산하지 않는다. 통화·가격 기준·환산 기준·대상 기간이 다르면 합산을 보류한다. 계약 금액 미공개는 0이 아닌 ‘미공개’다.

MVP 데이터는 조사 → 원문 보관 범위 확인 → 레코드 추출 → 사람 검토 → 공개 승인 → 버전 배포 순으로 관리한다. 매주 신규 자료 확인을 제안하되 전시 배포 버전은 고정하고 변경 때마다 검수한다. SIPRI는 해당 기관의 갱신 시점에 맞춰 재검토한다.

## 8. 최소 온톨로지

```text
군 ── 사용·관련 ── 무기체계 ── 수행 ── 임무
                         ├── 속함 ── 환경·기술 영역
                         ├── 관련 ── 획득사업 ── 이력 사건
                         ├── 제작·참여 ── 기업·기관 ── 공개 지역
                         └── 관련 ── 수출·협력 사건 ── 국가
공개 근거 ── 뒷받침 ── 개별 사실·사건·사업 설명
인수인계 초안 ── 참조 ── 승인된 직원용 문서 묶음
```

처음에는 stable ID와 관계 목록을 갖춘 JSON으로 구현한다. 관계형 저장소나 그래프 DB는 규모·검색 요구가 생기면 도입한다. 노드 그림을 보여주는 것만으로 온톨로지를 완성했다고 보지 않는다. 관계의 정의·분류·출처가 실제 필터와 검색에 사용되어야 한다.

공통 필드: id, nameKo, nameEn, description, status, asOf, sourceIds, reviewedAt, publicationStatus. 사건 필드: systemId, countryId, eventType, eventDate, datePrecision, agreementLevel, quantity, amount, currency, parentAgreementId. source 필드: title, publisher, url, publishedAt, checkedAt, locator, reuseTerms. AI 인용은 개별 사실과 source·locator를 연결한다.

좌표는 displayGeometry, locationRole, locationPrecision으로 구분한다. 설명용 장비 좌표와 실제 공개 산업 지역을 같은 의미로 저장하지 않는다. 원문 정보가 충돌하면 양쪽 근거와 검토 상태를 남긴다.

## 9. AI가 해결할 실제 문제

국민용: ‘K9은 어떤 역할인가요?’에 승인된 공개 근거로 짧고 쉬운 설명과 관련 체계를 안내한다. 숫자나 일정은 검증된 데이터에서 가져오고 근거를 붙인다. 직원용: 자료 묶음에서 사업 이력·용어·미결 사항을 뽑아 원문과 비교 가능한 초안을 만든다.

AI는 MVP의 데이터 검색 기능을 대체하지 않는다. 출처 없는 홍보 문구 생성이나 사실 자동 게시를 허용하지 않는다. 공개 인덱스와 직원 자료 인덱스는 분리한다. 서버만 AI 자격증명을 보관하며 공개 프론트에 비밀 키를 넣지 않는다.

전시 인터넷 단절 시 승인된 사전 설명·FAQ를 제공하고 ‘준비된 설명’으로 표시한다. 실시간 AI가 작동하는 것처럼 표현하지 않는다. 자유 질문은 재연결 안내를 제공한다. 공유에는 공개 콘텐츠와 필터 상태만 포함하고 개인 질문·직원 자료는 포함하지 않는다.

## 10. 전시 품질과 확산

시각 방향은 ‘디지털 과학관’: 깊은 남색, 읽기 쉬운 흰색 글자, 절제된 태극 색상 포인트, 선명한 지형과 좋은 장비 모델. 첨부 포스터의 AI 회로 배경은 공모 맥락 참고이며 UI를 그대로 복제할 시각 레퍼런스는 아니다. 전시 수준은 모델 품질·카메라 연출·콘텐츠·터치 응답·안정성이 함께 결정한다.

- 키오스크: 주요 터치 영역 48px 이상 제안, 핵심 글자 크기와 실제 패널 가독성 검증, 홈·뒤로·초기화 고정.
- 무조작 90초 후 초기화 예고, 계속하기로 취소. 대기 화면 복귀 시 이전 질문과 선택을 비움.
- 4K 전시 PC와 1080p 터치 환경을 각각 검증. GPU·메모리·디스플레이 모델은 미확정.
- 목표: 지정 전시 PC 1080p에서 일반 탐색 30fps 이상, 로컬 시작 5초 이내, 8시간 반복 운영 중 치명 오류 없음. 측정 전 보장하지 않음.
- 모델 LOD·압축·지연 로딩·해상도 제한. 모델 실패는 사진·설명 카드로 복구, WebGL 실패는 목록 화면으로 복구.
- 키보드·초점·스크린리더 설명·색 이외 구분·움직임 줄이기. 접근성은 별도 검증 후 판단.
- 한영 핵심 콘텐츠와 용어집, 영상이 있을 경우 자막. 원문 근거를 번역문과 연결.

확산 흐름: 현장 체험 → 관심 체계 1개 선택 → QR로 모바일 동일 화면 → 관련 체계·검증된 설명 탐색 → 출처가 포함된 공개 카드 공유. 공개 URL 배포는 후속 단계다. 원격 서비스가 없으면 QR 확산 기능의 완료로 간주하지 않는다.

박물관은 3분 교육·퀴즈, ADEX 성격의 전시는 공중·우주·합동 이야기, MADEX 성격의 전시는 해상·해병대 이야기를 기본 프리셋으로 제안한다. 행사 주최 측의 장비·브랜딩·네트워크 요구는 별도 확인한다. 동일 앱의 콘텐츠와 초기 시점만 바꾸어 운영한다.

평가 지표 제안: 첫 체계 선택까지 20초 이내, 처음 접하는 참가자 5명 중 4명이 임무·출처를 도움 없이 찾기, 체험 전후 3문항 이해도 비교, QR 이어보기 비율. 업무바통은 수동 정리 대비 걸린 시간·빠뜨린 항목·근거 오류·담당자 수정량을 측정한다. 모두 목표이며 실제 개선 실적은 아니다. 개인 식별 정보 없이 집계하고 전시 촬영·분석은 기관 정책에 따른다.

## 11. 구현 순서와 예상 일정

소규모 제작팀, 대표 모델 3개·공개자료 사용권 확보를 가정한 4~6주 초안이다. 한 사람이 자료조사·모델 제작까지 담당하면 더 길어질 수 있다. 공모 공식 마감은 포스터 이미지 외 요강으로 검증하지 않았으므로 이 일정을 제출 보장으로 해석하지 않는다.

1. 1주차: 실제 전시 PC·네트워크 확인, 한반도 좌표 데이터·모델 1개로 Cesium 기술 검증, 공개 사건 5개 수동 검수.
2. 2주차: 필터·체계 상세·국내/세계 지도·일관된 데이터 ID 구현. 대표 흐름을 끝까지 작동.
3. 3주차: 모델 3개·대표 체계 콘텐츠·사건 확대, 출처/기준일/사건 유형 검증, 3분 투어.
4. 4주차: 공개자료 AI와 별도 업무바통 문서 1묶음 시연, 원문 대조·승인 단계.
5. 5~6주차: 전시 패널 리허설·장시간 운영·오프라인·접근성·한영·모바일·QR 검증, 제작물 정리.

전시 납품물: 브라우저 앱+로컬 실행 패키지, 데이터/자산 출처 목록, 설치·복구 안내, 안내 투어 시나리오, 사용성·성능 검증 기록. 홍보 확장물: 체계 공유 카드, 설명 포스터, 투어 영상을 후보로 제안한다. 영상·웹 공개 배포는 이번 단계에서 제작하지 않았다.

## 12. 대표 검증 시나리오

1. 방문자가 ‘지상’을 누르고 K2를 선택한다. 임무와 출처를 읽고 세계 보기에서 폴란드 관련 사건을 찾는다. 계약과 인도를 혼동하지 않는지 관찰한다.
2. 해병대 필터를 적용한다. 해상·지상에 관련된 공개 체계를 함께 탐색하고 빈 결과도 명확히 안내한다.
3. 인터넷을 끊고 앱을 재시작한다. 지도·모델·근거 카드가 로컬에서 작동하고 AI의 준비된 설명 표시를 확인한다.
4. 업무바통에서 원문에 없는 일정 질문을 한다. 미확인 표시 후 원문 비교·수정·승인·내보내기를 수행한다.
5. QR을 개인 휴대폰으로 읽어 같은 체계·출처로 연결한다. 키오스크는 다음 관람객을 위해 초기화한다.

## 13. 다음 협의 항목

우선 하나의 방향을 추천한다: **전시 체험을 주 제품으로 만들고, 공개 웹은 같은 콘텐츠의 가벼운 확산 창구로, 업무바통은 분리된 시연으로 구성한다.**

다음 결정은 첫 공개 장소·화면 크기·PC 사양·인터넷 사용 가능 여부다. 이후 공식 공모 요강, 자료 승인 담당자, 모델 사용권 확보 가능성, 한영 범위와 예산을 정하면 제작 범위와 품질 목표를 확정할 수 있다.

## 2026-10-08 구현 현황

첫 시연은 실제 HTML5 MVP로 구현했습니다. 한반도 3D·세계 수출·지식 관계망·체계 도감에 검색과 공통 필터를 연결했습니다. 사용자 추가 요구에 따라 자동/가로/세로 화면, 좌측/하단 메뉴, 전시 크기 및 전체 화면을 제공합니다.

현재 데이터는 9개 체계·7개 출처·폴란드 계약 사례로 한정합니다. 전체 사업/수출 통계, 정밀 지형, 사실적인 모델, 정식 온톨로지 추론과 AI 업무 인수인계는 이 시연의 완료 범위에 포함하지 않습니다. 실행은 README, 실제 확인 결과는 docs/QA.md에 기록했습니다.
